# Bread Command Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make approved V6 the real extension fullpage wallet, port the bridge portal's real capabilities, and make the compact sidebar's fullscreen launcher unmistakable.

**Architecture:** Retain the wallet's existing App/provider/router/authorization stack and transaction owners. Add scoped Command presentation and memory-only drafts; port portal domain/provider functionality through wallet-native signing, transport and persistence. Shared components keep compact/native defaults; only the explicit launcher changes the compact sidebar.

**Tech Stack:** React 18, TypeScript, existing canonical UI/Radix/Framer Motion, Zustand/intercom, Dexie, viem/wagmi/AppKit, existing Miden/Epoch SDKs initially, Jest/RTL and Playwright. Use Node 22 and Yarn 1.

**Spec:** [Approved design](bread-command-integration-design.md), including the 2026-11-14 prominent-launcher amendment. Read it in full before this plan. The worktree is already isolated at `.worktrees/bread-command-integration`, branch `feat/bread-command-integration`.

## Review Focus

1. A sidebar picker/nested flow hides `data-home-actions`, or its scroll moves: the launcher must remain visible without covering the financial footer. Task 1 pins this.
2. A different account/RPC, stale balance result or unresolved privacy setting lands during navigation: never paint/store the previous account's data. Tasks 2-3 pin this.
3. Two realms resume one operation without Web Locks, or storage fails after broadcast: only one source write/solve may run and uncertainty must not become a fresh send. Tasks 9, 11-13 pin this.
4. An approval or async account/cap read outlives its quote: reject changed identities/contracts/minimums before the irreversible step, even if the UI still looks reviewed. Tasks 8, 10-13 pin this.
5. An old/recovered row or source-completed swap/bridge is opened: preserve legacy permission boundaries and show delivery/consumption separately from source completion. Tasks 5-7 and 14 pin this.
